# Принятые решения

Здесь записаны решения по неоднозначным местам задания. Во всех случаях выбирался самый полный вариант.

## Стек и инфраструктура

1. **Next.js 16 (App Router).** В Next 16 файл `middleware.ts` переименован в `proxy.ts`. Первая линия защиты маршрутов лежит в `src/proxy.ts` (это и есть «middleware» из задания).
2. **shadcn/ui.** Каталог `ui.shadcn.com` из среды разработки недоступен (сеть закрыта прокси), поэтому CLI `shadcn` запустить не удалось. Компоненты shadcn/ui (`button`, `input`, `card`, `dialog`, `dropdown-menu`, `table`, `badge`, `label`, `textarea`, `native-select`, `skeleton`, `progress`, `sonner`) лежат в `src/components/ui/` как исходники, как и задумано в shadcn. Внутри те же Radix UI, `class-variance-authority` и `tailwind-merge`. Стили переделаны под скевоморфный дизайн.
3. **Prisma 6, а не 7.** В Prisma 7 для SQLite нужны driver adapters и `prisma.config.ts`, а Prisma 6 — стабильная ветка с простым переключением SQLite ↔ PostgreSQL.
4. **Переключение на PostgreSQL через `.env`.** Prisma не умеет брать `provider` из переменной окружения. Скрипт `scripts/db-provider.mjs` смотрит на `DATABASE_URL` (`file:…` → sqlite, `postgres://`/`postgresql://` → postgresql), правит `provider` в `schema.prisma` и применяет схему: для SQLite — миграции из `prisma/migrations`, для PostgreSQL — `prisma db push`. Переключение проверено на реальном PostgreSQL 16: схема, сид, все страницы трёх ролей, проверки 403.
5. **Регистронезависимый поиск.** В SQLite `contains` не учитывает регистр только для латиницы. Поэтому у `User` есть поле `searchKey` (ФИО + логин в нижнем регистре, `ё → е`). Оно пишется при создании и изменении и одинаково работает в SQLite и PostgreSQL. Названия групп и данные ученика (десятки записей) фильтруются в памяти.
6. **Часовой пояс.** «Сегодня» считается в поясе центра `APP_TIMEZONE` (по умолчанию `Asia/Tashkent`). Даты уроков хранятся как полночь UTC календарного дня.
7. **Сессии Auth.js — JWT.** При этом каждая страница, server action и API route заново читает пользователя из БД. Поэтому деактивация (`isActive=false`) и удаление действуют сразу, даже при живой сессии.

## Доступ

8. **Три уровня проверки:** `proxy.ts` (нет сессии → `/login`, API → 401; раздел чужой роли → 403) → guard страницы/layout → проверка в каждом server action и API route (`src/lib/access.ts`).
9. **Настоящий HTTP 403.** Включён `experimental.authInterrupts` и используется `forbidden()`. Проверка доступа к конкретной группе и ученику стоит в `layout.tsx` маршрута, до границы `loading.tsx`: иначе потоковая отдача успела бы отправить статус 200. Несуществующая запись даёт 404.
10. **Админ в server actions учителя.** Действия журнала (посещаемость, оценки, ДЗ) разрешены ролям TEACHER и ADMIN, потому что у админа полный доступ. Учитель проходит проверку «группа моя», ученик в действии должен состоять в группе урока.
11. **Учитель видит «своего ученика»,** если тот состоит хотя бы в одной его группе. Рейтинг и история такого ученика учителю показываются только по его группам.
12. **API ученику:** `/api/groups/[id]` отдаёт ученику сведения только о своей группе и без состава, `/api/students/[id]/rating` — только свой рейтинг.

## Рейтинг (`src/lib/rating.ts`)

13. **Неполные данные — пропорциональный пересчёт.** Часть без данных показывается как «нет данных» (не ноль). Итог = сумма баллов доступных частей / сумма их максимумов × 100. Если данные есть по всем трём частям, это просто сумма баллов. Если данных нет совсем, итог тоже «нет данных». Пример: только оценки со средней 4 → 40 из 50 → итог 80.
14. **Посещаемость** считается по урокам, где ученику поставлена отметка. Неотмеченные уроки (в том числе будущие, созданные из расписания) не считаются пропусками. EXCUSED исключается из знаменателя, LATE = 0.5.
15. **ДЗ:** «все задания» — это задания групп ученика со сроком до сегодняшнего дня, плюс уже отмеченные задания с будущим сроком. Задание с прошедшим сроком без отметки считается NOT_DONE. Задание с будущим сроком без отметки пока не учитывается.
16. **Период «текущий месяц»:** оценки — по дате оценки, посещаемость — по дате урока, ДЗ — по сроку сдачи, всё в пределах календарного месяца.
17. **Округление:** баллы частей и итог округляются до 0.1 от точного значения (итог не складывается из округлённых частей).
18. **Рейтинг учителя** — среднее итоговых рейтингов его учеников, посчитанных по его группам. Ученики без данных не участвуют.
19. **Цвета:** ≥80 зелёный, 50–79.9 жёлтый, <50 красный, «нет данных» — нейтральный.

## Расписание, журнал, ДЗ

20. **Уроки генерируются из `ScheduleSlot`** при каждом открытии недельного расписания (для показанной недели), журнала группы (−30…+7 дней), главной учителя и ученика. Ещё уроки создаются сразу при добавлении слота (на 2 недели) и кнопкой админа «Создать уроки на 2 недели». Повторно урок не создаётся: ключ уникальности — группа, дата и время начала.
21. **Удаление слота** удаляет только будущие уроки этого слота без отметок и оценок. Прошедшие уроки остаются в истории.
22. **Будущий урок** можно открыть и записать тему, но посещаемость и оценки ставятся с дня урока (сервер отвечает понятной ошибкой).
23. **Несколько оценок за урок** разрешены (например, за работу на уроке и за ответ у доски). В журнале они выводятся рядом.
24. **Удаление учителя** оставляет его группы без учителя (`SetNull`). Удаление ученика или группы каскадно удаляет их оценки, посещаемость и отметки ДЗ. Перед удалением показывается предупреждение. Предмет, по которому есть группы, удалить нельзя.
25. **Учитель для группы** должен вести предмет группы (проверяется на сервере).

## Интерфейс и дизайн

26. **Скевоморфизм «кабинет старого учителя»** (дополнение к заданию заменяет пункт «Дизайн»). Материалы вынесены в токены в `src/app/globals.css`: `--wood`, `--leather`, `--stitch`, `--paper` (#F5EFE0), `--brass` (#B8893A), `--ink` (#2B1D14) и другие. Текстуры сделаны только на CSS: градиенты, тени и встроенный SVG-шум (`feTurbulence`), без картинок.
27. **Шрифты:** PT Serif (заголовки), PT Sans (текст), Caveat (оценки и записи «от руки»), все с кириллицей, через `next/font`.
28. **Контраст WCAG AA** проверен расчётом для всех пар токенов в обеих темах (≥ 4.5:1). Невыбранный штамп отличается от выбранного пунктирной рамкой, а не прозрачностью, чтобы текст оставался контрастным.
29. **Тёмная тема «вечерний кабинет»:** тёмное дерево с тёплым радиальным светом лампы, бумага в полутени, светлые чернила. Переключение: светлая / тёмная / системная.
30. **Анимации** лёгкие (штамп, стрелка прибора, появление). При `prefers-reduced-motion: reduce` все анимации и переходы отключаются.
31. **Фильтры и поиск списков** — обычные GET-формы: работают без JavaScript, а состояние хранится в URL, так что ссылкой можно поделиться.
32. **Список «Мои группы» учителя** (`/teacher/groups`) и **расписание учителя** (`/teacher/schedule`) добавлены сверх списка страниц: в задании требуется «недельный вид для каждой роли» и «все списки с поиском».

## Тесты

33. **E2E на отдельной базе** `prisma/e2e.db`. Перед прогоном файл удаляется и создаётся заново (`migrate deploy` + сид). `prisma migrate reset` не используется: Prisma запрещает его запуск ИИ-агентом без согласия пользователя, а для отдельного тестового файла сброс и не нужен. Рабочая `dev.db` не затрагивается.
34. **Каждый сценарий Playwright** прогоняется на двух ширинах: 1440px (desktop) и 375px (mobile).

## Доработки после проверки

35. **История ученика листается полностью.** У админа и учителя история оценок, посещаемости и ДЗ ученика разбита на страницы по 10 записей (`gp`, `ap`, `hp` в URL), а не обрезана последними записями. Так выполнено требование «история по каждому ученику».
36. **Поиск и пагинация внутри страниц:** списки учеников группы (админ и учитель) и учеников в профиле учителя. Параметры `q` и `sp`.
37. **Смена собственного пароля** (`/account`) для всех ролей: нужен текущий пароль, новый — не короче 6 символов и с подтверждением. Без этого у админа не было способа сменить демо-пароль `admin123`, а сайт открыт в интернете.
38. **Формы не теряют введённые данные при ошибке.** React 19 после отправки формы через `action={...}` сам очищает поля, даже если сервер вернул ошибку валидации. Все формы отправляются через `onSubmit` → `startTransition(dispatch)` (`submitWith` в `form-kit.tsx`) и очищаются явно только после успеха там, где это нужно.
39. **Параллельное создание уроков.** Если два запроса одновременно генерируют один урок, конфликт уникальности (P2002) безопасно игнорируется.
40. **Автодеплой.** Скрипт `vercel-build`: `db:setup` (для PostgreSQL — `db push` через прямое подключение `DATABASE_URL_UNPOOLED`/`POSTGRES_URL_NON_POOLING`, если оно есть) → сид только в пустую базу (`seed-if-empty`) → сборка. Пароль админа для первого сида задаётся `SEED_ADMIN_PASSWORD`. Сценарий проверен двумя прогонами подряд на PostgreSQL 16: первый создал данные, второй их не тронул. Сам деплой на Vercel из этой среды не проверялся: нет доступа к аккаунту.

## Доработка: профили, рейтинги, устройства, безопасность

41. **Ник — главное имя, логин остаётся для входа.** Логин задаёт администратор и человек его не меняет. Ник уникален без учёта регистра и «ё/е» (`nicknameKey`), проверяется на лету и повторно на сервере. Пока ник не выбран, везде показывается логин.
42. **Мастер первого входа обязателен.** Пока не выбраны ник и свой пароль (у аккаунтов с временным паролем), кабинеты, server actions и API закрыты (`needsOnboarding`), остаётся только мастер и выход.
43. **Фото.** Сервер перекодирует любую загрузку в WebP 512×512 без EXIF (защита от подделанных файлов и утечки геометки), хранит через `StorageProvider` (папка или S3). Файл получает новый ключ при каждой смене, поэтому кэш браузера не мешает.
44. **Права на профиль.** Свой профиль правит только владелец (id берётся из сессии, а не из формы). Администратор правит любой профиль, и запись о правке попадает в журнал; значения телефона, почты и даты рождения в журнал не пишутся (только «изменено»).
45. **Формулы рейтинга не менялись.** Ранги, динамика, места, награды и подсказки — надстройка над теми же данными. Динамика считается «рейтинг на дату» тем же расчётом. Подсказки «что улучшить» считают пользу действия по настоящим формулам.
46. **Доска почёта:** только ник и баллы. Ученик может скрыть себя; он по-прежнему видит своё место.
47. **Достижения не отбираются:** выданное раз остаётся. Конфетти показывается один раз (по флагу `seen`), при `prefers-reduced-motion` не рисуется совсем.
48. **Адаптивность.** Боковое меню от 1024px, ниже — нижняя панель (у админа 4 пункта и «Ещё», чтобы не сжимать 7 пунктов). Таблицы на телефоне превращаются в карточки с подписями. Все цели нажатия не меньше 44px, поля ввода 16px (iPhone не приближает экран). Проверка автоматическая (`npm run test:devices`) на эмуляции Chromium.
49. **«Кому нужно внимание».** Причины: рейтинг ниже 50, два пропуска подряд (уважительные не считаются и серию не рвут), два из трёх последних ДЗ не сделаны, средняя трёх последних оценок ниже 3. Порогов в интерфейсе нет: правила описаны в подсказке «?».
50. **Заметки об ученике** видны только автору и администратору (только чтение). Писать можно только об ученике из своей группы; чужая заметка для учителя выглядит как несуществующая.
51. **Безопасность входа — без блокировок.** Каждая попытка входа записывается (`LoginAttempt`: логин, устройство из User-Agent, IP из `X-Forwarded-For`), но результат входа решает только пароль. На пятой неудаче подряд на существующий аккаунт создаётся одна тревога (`SecurityAlert`) и уведомление каждому активному администратору; дальнейшие неудачи только обновляют счётчик тревоги. Серию обрывают успешный вход и решение администратора. Неизвестные логины тревог не создают (чтобы нельзя было засорить список выдуманными логинами). Записи старше 90 дней удаляются.
52. **Решения по тревоге** — только вручную: «Всё в порядке», «Сбросить пароль» (временный пароль показывается один раз, `mustChangePassword`), «Заблокировать аккаунт», «Разблокировать». Свой аккаунт заблокировать или сбросить нельзя. Каждое решение пишется в журнал действий.
53. **Известная особенность Auth.js:** middleware обновляет cookie сессии на каждом запросе, поэтому фоновая предзагрузка страницы, дошедшая уже после выхода, может на мгновение вернуть сессию. Для e2e выход считается завершённым, когда cookie сессии удалена (`logout` в `tests/e2e/helpers.ts`); на работу сайта это не влияет.
