## Этап 7. Безопасность и уведомления админу — выполнен
- [x] Пароли — bcrypt; права проверяются на сервере в каждой странице, действии и API; ввод проверяется zod; XSS — React экранирует вывод, «сырого» HTML нет; SQL-инъекций нет — только Prisma с параметрами; чужие контакты и даты рождения не показываются (учителю — только ник, имя и «о себе»).
- [x] **Автоблокировок нет**: `authorize` только записывает попытку (`LoginAttempt`) и не задерживает, не ограничивает и не блокирует. Правильный пароль пускает сразу, даже после десятков неудач (проверено e2e).
- [x] 5 неудачных входов подряд на один существующий аккаунт → `SecurityAlert` + уведомление (`Notification`) каждому активному администратору. Серию обрывают успешный вход и решение админа. Дальнейшие неудачи обновляют ту же тревогу без новых уведомлений. Неизвестные логины тревог не создают.
- [x] Колокольчик (боковая панель на ноутбуке, шапка на телефоне) с числом непрочитанного, список, «Прочитано»; баннер на главной админа.
- [x] Страница «Безопасность» (`/admin/security`): кто (ник, логин), сколько попыток, когда (с — по), устройство («Safari · iPhone»), IP; вкладки «Требуют решения» / «Решённые».
- [x] Кнопки с подтверждением: «Всё в порядке», «Сбросить пароль» (временный пароль показывается один раз, человек выбирает свой при входе), «Заблокировать аккаунт» (вручную), «Разблокировать». Свой аккаунт заблокировать/сбросить нельзя. Все решения пишутся в журнал действий.
- [x] Мобильная нижняя панель админа: 4 пункта + «Ещё» (Расписание, Журнал, Безопасность).
- [x] Тесты: +7 юнит-тестов (правила серии, порог, определение устройства, IP), +6 e2e (× desktop и mobile): тишина до 5-й попытки, тревога на 5-й, отсутствие блокировок, «Всё в порядке», сброс пароля, блокировка и разблокировка, 403 для учителя и ученика.
